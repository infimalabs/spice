## Identity and authority

| Label | Invariant |
| --- | --- |
| <a id="identity-a-task-s-born-stamp-is-its-only-stored-identity"></a>**A task's `born` stamp is its only stored identity** | The rendered handle derives a stem from the topic's rightmost component and is never stored, so re-homing renames for free. That abbreviation is presentation only: every other surface treats the complete topic as one exact path. Every surface resolves a handle by its stamp alone: a handle rendered under another topic names the same task, the stem never grants or narrows visibility, and answers render the current handle. Task stamps and steering keys resolve a collision by advancing to the next free later microsecond; a task batch retains authored order. Existing identities never move. Stamp order is not creation chronology; journal sequence and durable topic origin are. |
| <a id="identity-an-occupant-address-is-its-birth-position"></a>**An occupant address is its birth position** | An occupant's only peer address is the journal position of the one `lane::started` fact recording its birth. It is derived from that fact, never minted or stored, so occupants started in the same instant keep distinct addresses. Proof reads exactly the addressed position and refuses rather than picking when no birth, a non-birth fact, or a repeated birth is found. |
| <a id="identity-an-address-executes-only-for-its-seated-occupant"></a>**An address executes only for its seated occupant** | An address resolves only while the residency seats that exact occupant on its birth lane; it never follows the lane to a successor. Resident restart adoption keeps the occupant and its address. Every wake, resume, import, and renewal seats a different occupant with its own address, and the predecessor's address expires. What an address already published is [bound to its lane](#steering-an-authored-syn-packet-admits-each-proved-recipient), not to the address. |
| <a id="identity-every-code-a-lane-has-shown-selects-that-lane"></a>**Every code a lane has shown selects that lane** | Lane-targeting commands (`spice lane` controls, `spice inbox`, `spice steer`, `spice room score`) take an occupant code where they name a lane. Any `lane::started` position the lane recorded selects it whether it names the current occupant or a predecessor, including when the lane is vacant. Resolution uses one board snapshot with the lane's residency; the answer names the lane's newest code and how many occupants started since. A position that records no birth refuses as unknown, and a code whose lane has left residency refuses as removed rather than reaching another lane. Names never select. This selection targets a lane, never an occupant: a `SYN` address still [executes only for its seated occupant](#identity-an-address-executes-only-for-its-seated-occupant). |
| <a id="identity-lane-discovery-separates-a-stable-code-from-the-current-peer-address"></a>**Lane discovery separates a stable lane code from the current peer address** | The session briefing names the reader's own exact occupant address and its teammates' current addresses. `spice lane` and `spice lane list` show each lane's newest proved occupant `code`; the bounded list also carries its current canonical team, claim, seat state, and exact peer `address` in text and JSON, directly from one retained residency snapshot. A team or occupant change appears on the next read. A vacant lane retains its newest code for lane selection while its exact peer address remains `unavailable:vacant`; a lane that has never started omits the code. An occupied lane's newest code equals its executable current address. `lane list` keeps canonical lane UUIDs out of its rows and continuations: `--after` uses the row's code, with an opaque cursor only for a lane that has no birth code. With no lanes, text says none are seated and names `spice lane add [WORKTREE]` as the next step, while `--json` remains an empty list. |
| <a id="identity-a-principal-is-born-once-by-an-explicit-admission"></a>**A principal is born once by an explicit admission** | `spice principal admit [--name NAME] [--email EMAIL] [--operator]` journals one `principal::admitted` fact naming a fresh durable external identity, its optional profile and its roles; that identity and its admission position never change. A principal may represent a person, automation, fleet, service, or another external system. The admission reply shows its connection capability once while the journal retains only the digest. Profile edits, role changes, capability retirement, administrative listing, and the app's **Principals** section operate on that same head. Git may seed a person's profile but never becomes display or routing authority. A resident's first start on a journal with no principal admits the repository owner from Git identity with the operator role; later starts admit nobody. Principal administration is operator-only, and no mutation may leave the repository without a connectable operator. No principal carries a SYN selector or addressing route. |
| <a id="identity-principal-mutations-retain-the-subjects-causal-origin"></a>**Principal mutations retain the subject's causal origin** | A profile edit, role grant or revocation, and capability retirement continue the target principal head's causal origin across resident generations. The fact actor names the operator who made the change; the origin names the principal thread being changed. The head-position guard still refuses concurrent replacement, and unrelated fact chains remain unable to cross origin boundaries. |
| <a id="identity-a-principal-code-is-its-birth-position"></a>**A principal code is its birth position** | A principal's code is the journal position of the `principal::admitted` fact that bore it, spelled as shortest-form vowel-free base 52. It is derived from that birth and never stored, so profile, role, and capability changes never move it and no two principals share one. A spelling resolves only against principal admissions. The connected directory, `spice principal list`, and the app's **Principals** section expose it. The code identifies a durable principal but grants no delivery, wake, inbox, role, capability, or command target; principal steering uses exact input authority, never a code as an audience. |
| <a id="identity-operator-authority-is-a-principals-current-role"></a>**Operator authority is a principal's current role** | One predicate decides operator authority: does the acting principal's current role head hold the operator role? An empty production role book grants no authority; startup records the first principal's admission before serving commands. Operator-only commands and controls, connected-command admission, lane selection, steering wake, and operator-direction recognition all ask it. Each connection authenticates through its own principal capability and authors as `principal:<principal>`. The app bootstrap serves the repository owner's capability only after its access boundary admits a capability-less opener; an opener presenting a capability receives only that exact still-authorized principal. Immutable history keeps naming the principal that wrote it: a later role change never reattributes facts. |
| <a id="identity-a-principal-reads-under-its-recorded-profile"></a>**A principal reads under its recorded profile** | Every surface naming a principal uses that principal's optional recorded profile, never Git configuration. The directory carries every principal's immutable [code](#identity-a-principal-code-is-its-birth-position) and presentation in birth order. A profile supplies initials and optional Gravatar decoration to the app alone; agent-facing surfaces and CLI text attribute a principal by its code, so a profile edit never changes attribution. Administrative principal surfaces keep the full recorded profile. Lane and Spice actors retain their own presentation. JSON and exported ledgers carry actors without presentation decoration. |
| <a id="identity-a-principal-route-reaches-the-principal-it-answers"></a>**A principal route reaches the principal it answers** | A lane's SYN naming `#KEY` of principal direction opens one steering input addressed to exactly the principal that sent that direction, read directly from the actor its authority records. Outside a lane, `spice room inbox` reads as the local owner and pages only the pending inputs addressed to it, by key; the app shows an input once its source text names this principal, or when that read fails. Addressing stays `#KEY` and `#TASK`: a principal code attributes and is never a selector. |
| <a id="identity-every-fact-has-exactly-one-authority"></a>**Every fact has exactly one authority** | Consumers ask the owner rather than re-deriving from a cheaper nearby source. |
| <a id="identity-a-lane-command-stays-in-its-launch-repository"></a>**A lane command stays in its launch repository** | A lane's installed Git-common appliance identifies the repository authority that launched it. When that lane addresses a healthy resident from another repository, the client refuses before opening the lane surface or submitting a command, names the addressed authority, and directs the lane to the operator or an explicit document handoff; no identity or fact crosses repositories. An absent lane surface under the same Git-common authority remains a resident-publication handoff and keeps the ordinary bounded wait. Operator commands carry no lane repository identity and are unchanged. |
| <a id="identity-one-kernel-owner-bounds-each-child-process-tree"></a>**One kernel owner bounds each child process tree** | Sill is the appliance process boundary. Unix launches use a new process group; Windows launches start suspended, enter a kill-on-close Job Object before their primary thread resumes, and settle only after both the root handle and the Job's active-process count are terminal. Cancellation and runtime expiry first request the platform's graceful group interruption, then force the whole owner after the declared grace and require kernel-observed reap within the declared bound. Exit, timeout, cancellation, capture failure, cleanup failure, and resource usage remain typed. A holder that keeps only a group's id, such as a resident ending a detached supervisor's occupant or a keeper sweeping its command, reaches the whole tree through sill's group signal: Unix signals the process group, while Windows opens the owner-only Job named for that group, interrupts with `CTRL_BREAK`, and forces by terminating the Job. An emptied or unknown group refuses as not found, and a stale name refuses a new launch rather than adopting it. Git and every other supervised caller use this boundary rather than owning PIDs, descendant probes, signals, or raw child pipes independently. A detached lane supervisor admits a replacement resident through the held runtime lock without changing its occupant; when that lock, the repository, or the supervisor state directory stays absent for one lane lease, it cancels the Sill owner and closes the resource child's input. |
| <a id="identity-a-resume-cursor-belongs-to-one-exact-stream"></a>**A resume cursor belongs to one exact stream** | One authenticated stream carries an authoritative snapshot followed by accepted facts in monotone sequence within one resident epoch, applied exactly once in that order. A cursor resumes only its exact application generation and resident epoch; a mismatch or gap requires a fresh snapshot rather than a guessed merge. |
| <a id="identity-durable-facts-and-heads-remain-distinct-from-rebuildable-index-rows"></a>**Durable facts and heads remain distinct from rebuildable index rows** | A derived index may share the authority store and transaction, but rebuilding it never mutates immutable facts or heads. |
| <a id="identity-a-projection-family-must-declare-its-source"></a>**A projection family must declare its source** | A projection family declares its source, its progress record, its replay horizon, its refill, and what it can still say when the source no longer reaches back. |
| <a id="identity-a-session-owes-one-open-design-request"></a>**A lane owes at most one open Design request before allocation** | A claim or lane name alone creates no Design request. Each lane retains one bounded profile of successful-task and authored-conversation evidence across every occupant and vendor session it hosts, seated or vacant. A successful completion, settled conversation message, completed profile warm, or session resume is one opportunity to evaluate that lane's profile; an open Design's activation or statement revision is one opportunity for every lane, so its cost is bounded by lanes times retained cards. The resident fits the 256 most recently revised task statements, open or completed, as one document-frequency corpus and compares every retained task-statement, task-completion, whole-message, and passage view with each current undeferred open Design's title, description, and itemized open questions. Terms keep the Design-awareness normalization; each document contributes a term once to document frequency, a document term appearing $c$ times has weight $(1+\ln c)(1+\ln((N+1)/(df+1)))\,r^{1/2}$, where $r=(1+\ln((M+1)/(m+1)))/(1+\ln(M+1))$ when $m$ of the $M$ whole-message conversation views held by the profiles of lanes with a residency session use the term, counted only when the statement corpus refits, and $r=1$ while none are held; an occupant's exit or lane renewal leaves the lane's conversation in the background, removing the lane drops it, and the current fit is unchanged until the next refit. Sparse vectors are L2-normalized. A whole Design qualifies at the floor its maturity alone sets: wide 0.08 while unsteeped and narrow 0.16 once steeped; grouping never moves it. Whole-statement scoring dilutes vocabulary specific to one question, so each current question of every open Design also competes independently, at any standing, when its text read with the problem sentence clears the item floor of 0.16 against an independent retained card not consumed for that question. Every request includes all and only its selected Design's independently qualified questions its lane has not answered: each clears the request's applicable wide, narrow or item floor against its own strongest eligible card, with no question-count cap and no unmatched padding. A Design with questions but none qualifying forms no request, while a questionless Design can qualify whole. Candidates and listed questions rank by unmet feedback need before cosine: unheard, then lacking agreement (unopposed or contested), then concurred, and within one standing fewer independent contributing lanes, never raw charge or invitation counts. A whole Design stands for the neediest question it actually lists. At equal need a whole Design precedes a question; highest finite cosine wins within one kind, then durable Design identity and statement order. A lower floor changes qualification, not score ranking. One opportunity selects at most one Design and one lane has at most one unanswered invitation. While one is owed, an opportunity still scores the current cards: only a whole Design strictly outranking the owed Design under the same corpus and reach floor replaces it; equal or lower matches and question candidates record nothing, and an owed Design below its floor bars nothing. The Spice-owned `room::noticed` fact names the exact Design statement, lane, the occupant and session its residency row names, compaction boundary, opportunity, scored admission (reach, cosine, floor and fit generation), primary retained evidence and bounded authored excerpt, at most six strongest weighted-overlap terms sorted by spelling, and each asked question's position, text identity and state. Each selected question additionally retains its own supporting card, bounded excerpt and scored qualification under the same fit and reach; different questions may use different cards. Admission refuses duplicate question identities, an empty item request, self-supporting evidence, unbounded excerpts and inconsistent question qualifications. Conversation-only opportunities fabricate no task, claim or completion. A request and its answer belong to the logical lane, not an occupant or vendor session: renewal, a fresh session identity, compaction and resident restart never reopen one. A Design is asked whole at most once per lane and statement revision; when every current item concurs no whole request is formed, but otherwise eligible questions remain eligible. Before ranking either reach, each question the lane ever contributed against is excluded, and so is each question listed by a request the lane left; a question is its content, so a reworded one is another question. A questionless whole candidate is excluded after any own room record at its statement revision. Answering one question does not retire another, and an answer to a nonmatching, unlisted question does not exclude an otherwise qualified whole candidate. Whole invitations and question-specific offers retain separate evidence-consumption history: only a question-specific offer consumes its listed questions under their own immutable supporting evidence identities, never under an unrelated leading card. Consumed pairs are filtered before selecting each question's best card, so an old strongest card cannot hide a new qualifying one. An unanswered request retires nothing: once released, its questions may be asked again under eligible evidence. A statement revision is a new ask: it resets whole-ask and consumption history and may select the lane again, once. Compaction creates neither evidence nor an opportunity. When the recorded occupant is seated, it is told once by a private non-waking notice naming the Design, its asked questions and `task next`; nothing retries or restates it, a vacant lane's request is recorded without telling, starting or waking anyone, and the lane's next occupant reads the owed request from `task next`. A listed request settles on the lane's own later contribution against any listed question or its `spice room leave HANDLE --clause TEXT`; a charge changes only its question's standing, and a leave records no question charge or agreement. Another actor's post or an open question leaves it owed. A questionless whole request settles on any later room record by the lane. The lane may later receive a different Design or unretired question; a declined, closed, deleted, deferred or intake Design does not retarget that opportunity. Recording revalidates the exact Design statement and filed undeferred open standing, that the lane's residency row still names the target occupant and session, that the lane has neither a newer request nor an answer, and every immutable supporting task or transcript source. `task next` revalidates the Design's standing and statement, the lane's answer, and every supporting source, never the occupant, session or compaction; deferral ends the request and its listening until wake makes it current. A changed Design or a lost or replaced evidence source refuses or releases. The request quotes the current title, stored problem sentence, opportunity, matched terms and supporting work, as earlier experience, not the current assignment. Every request explains that a charge's sign weighs whether the answer changes what gets built, positive that it does and negative that it does not, never a vote for one named alternative; a brief ±1 view from existing work and knowledge is complete without citation, new research or novelty; a 0 or ±2 charge adds a checked real source; agreement is the lane's own view, not volume; leave is complete when the lane genuinely has no view after considering its matched work, not merely because it lacks a citation or new finding. Multiple questions welcome a brief comment on any one, several or all. Each offered question is quoted with position, state and lanes, most needed first, and its own supporting work and citation guidance. A contested question asks a previous contributor for a strength-2 re-charge and an outside lane for its own charge, without prescribing a sign. Task evidence may be cited when a charge rests on it; matched conversation is not citable. `task next` renders this text whole. Task support says implemented, diagnosed or planned, or reviewed according to the supporting claim's phase and names exact task, statement and completion or claim with `spice task show TASK --history`; conversation support names its exact source, member, byte and length with the post-compaction `spice session context` command; both quote the recorded non-empty whitespace-collapsed excerpt of at most 240 characters. The invitation adds no claim, workflow state, participation, steering, wake, assignment, implementation authority or new investigation. `spice room awareness HANDLE` (`spice://task/HANDLE/room/awareness`) pages durable requests in journal order with their admission reach, score and floor. |
| <a id="identity-an-undecided-design-uses-the-decision-match-floor"></a>**An undecided Design uses the decision match floor** | While an open Design's completed pass awaits the operator's decision, its durable cycle overrides the usual maturity-owned whole and item invitation floors with 0.24. The wide, narrow, or item reach remains recorded as match provenance; the notice records 0.24 as the floor that admitted it. A decision removes the override, returning floor ownership to current maturity. |
| <a id="identity-a-design-request-cannot-seed-its-own-match"></a>**A Design request cannot seed its own match** | A settled assistant message remains conversation evidence, including prose authored while handling a Design request, but it names every Design whose request notice reached its turn, whether in the prompt that opened the turn or in an aside that landed inside it, until the turn completes; any other notice landing mid-turn leaves those causes in place. Matching excludes that card only when scoring one of those same Designs or its question items; the card remains eligible for every unrelated Design. Live capture and historical profile warming derive the same causes from the same sealed notices, including when a backward history window crosses the middle of a turn. A contribution or leave is the durable response to the request; discussion caused by the request cannot feed back into another invitation for itself. |
| <a id="identity-a-closing-sweep-attempts-every-vacated-seat"></a>**A closing sweep attempts every vacated seat** | Vacancy entries remain in the seat ledger until a message batch exists. A successful take orders them by lane and occupant, presents every closing tape even after an earlier refusal or non-store fault, removes each exact occupant binding after its own presentation attempt, commits the batch, and only then returns the first terminal outcome. Store faults remain diagnostic and deferred; lane profiles, retained evidence, and the fitted matcher generation remain unchanged. |
| <a id="identity-a-designs-newest-decision-feedback-reaches-its-active-holder-once"></a>**A Design's newest decision feedback reaches its active holder once** | A resolved decision is the operator's immutable, pass-scoped verdict on every offered output, with optional per-output and overall comments; a return is the pass-scoped reason it went back. Neither changes the statement, workflow, or claim, and only accepted outputs gain authorization. `spice room history HANDLE` shows each complete decision. The newest decision carrying a rejected output, output comment, or overall comment is the Design's next input until an active holder has received it. After each task, claim, residency, or decision-authority change, the resident finds each open undeferred Design whose active claim an occupied lane holds and skips input already named by a `room::relayed` record. Otherwise the exact occupant's supervisor must confirm the private notice before the resident commits one Spice-owned `room::relayed` record naming the decision, lane, occupant, and exact claim win; missing doors, occupant mismatch, write failure, or claim movement record nothing. A claim race leaves the input owed to the new holder. A crash after confirmation but before recording may repeat the same purpose-coalesced informational notice but creates no duplicate authority. Unheld or deferred Designs retain the input until a later active claim, and restart does not redeliver a completed record. The notice names the Design, decision, every verdict comment and overall comment, clipped to one datagram while history keeps it whole; it needs no acknowledgment and starts no work. |
| <a id="identity-a-room-observation-records-before-any-listener-catch-up"></a>**A room observation records before any listener catch-up** | `spice room post HANDLE TEXT` publishes one observation, under its command identity, in any non-deleted task's room. Current listeners receive it through bounded catch-up; its author does not. The browser clears the composer only after success. While no lane listens and no later lane contribution, message, or leave proves receipt, the card carries an accessible Unheard mark. Recording creates no acknowledgment, claim, wake, interruption, participation, or listening authority. A deleted anchor refuses; settled-room history and receipts remain readable. |
| <a id="identity-no-room-command-pushes-a-design"></a>**Room publication never assigns a Design** | `spice room post` records an undirected observation, `spice room contribute` answers a problem-space request, and `spice room leave` declines one; none creates a claim or task association. Principal `room ack|fin|nak` controls an existing input rather than assigning its Design. The operator puts a lane on an open Design by telling it to `spice task capture HANDLE`; the lane acquires the anchor only through ordinary native task possession, and controlled drafts never allocate. |
| <a id="identity-a-room-reads-back-from-its-owning-sources"></a>**A room reads back from its owning sources** | `spice room history HANDLE` and `spice://task/HANDLE/room` resolve the handle to its born stamp and page whole publications oldest first. Each row names its sender, agent author, directed routes, and each room-anchored line disposition of either endpoint kind exactly once, with the body directive it carried. Principal-post text comes from its journal fact and packet text from the author's tape. Missing bytes render typed unavailable rather than empty; a withheld page continues at the first withheld publication. Reading joins, acknowledges, delivers, and wakes nothing. |
| <a id="identity-principal-line-controls-are-attributed-commands"></a>**Principal line controls are attributed commands** | `spice room ack|fin KEY [BODY]` and `spice room nak KEY [REASON]` control one steering input addressed to the acting principal through the same line action and body admission a lane's `ACK|FIN|NAK KEY` prose uses; no endpoint has its own receipt grammar. The client resolves the agent-visible key to its exact input and submits one `steer::line-control`; a key naming no input, or an input addressed to a lane, refuses before submission, and invalid, stale or wrong-endpoint authority refuses without writing. Bare ACK, or exactly `ok`, `noted`, `thanks` or `+1`, marks the input seen; ACK with other text continues the line, FIN closes it with a final body and NAK declines it. A body travels to the lane as one ordinary steering directive needing the Operator role; a body refused for authority or a closed line answers body-unsent while the authorized control commits. |
| <a id="identity-a-lane-leaves-a-room-by-an-attributed-act"></a>**A lane leaves a room by an attributed act** | `spice room leave HANDLE --clause TEXT` records one lane-attributed leave only to decline the Design request it owes there; owing none, it refuses `room::leave-nothing-owed` naming its native duties and writes nothing. A later request restores listening only from that new authority; skipped publications do not replay. Packets and contributions create no attention. Leaving never frees a claim or settles a delivery. |
| <a id="identity-a-lane-contributes-typed-problem-space-records-to-an-open-design"></a>**A lane contributes typed problem-space records to an open Design** | `spice room contribute HANDLE --charge=C --question HEX [--cite KEY...] TEXT` or `spice room contribute HANDLE --ask TEXT` appends one immutable `room::contributed` publication to an open Design's room: one whose current heads have Design intent, pending status, no completion, and phase `design`. The record names a charge from -2 to +2 or a question; the question item it weighs, the digest of that item's normalized text, which a charge requires; `--question HEX` is any digest prefix naming exactly one question of the Design statement head the command witnessed, refused `room::contribution-question-stale` when none begins with it and `room::contribution-question-ambiguous` when several do, each listing the current questions with their handles, and admission refuses an item outside that head's list as stale; its lane author as actor, its time, its trimmed nonempty text of at most 4096 bytes, and zero to eight distinct exact sources. A ±1 charge is an opinion; a 0 or ±2 charge cites at least one source. Each KEY resolves by form before submission: a key holding `/`, `.` or `:` to repository source `[COMMIT:]PATH[:L1-L2]`, one repository-relative file or line range read at `COMMIT` (a full id or a unique prefix of at least four hex digits) or else at the lane's HEAD; otherwise a task handle or stamp to `{"kind":"journal","fact":"SEQ"}` at that task's statement head, a publication stamp to `{"kind":"contribution","room":"DESIGN","publication":"PUBLICATION"}` in this room, a base-52 code to that journal fact, and a hex digest to `{"kind":"artifact","digest":"DIGEST"}`; an unknown handle or unreadable key refuses. The answer names the room, the publication, the kind, and `source`, the one canonical contribution spelling that cites it, which a decision source takes unchanged with no journal lookup or sequence encoding. Only a lane contributes, under its own actor. Admission witnesses the Design's statement and workflow heads and every source at one snapshot: a journal fact at or before that snapshot, a contribution published in its named room before it, a transcript hunk the tape still reads, a repository file or line range at its resolved commit, or an artifact retained on that Design. A missing, hidden, changed, unreadable, or unsupported source refuses `room::contribution-source-unavailable` naming it, and a concluded Design refuses `room::contribution-design-concluded`. At commit the journal applies the same actor, bounds, item, citation, and openness checks again, requires the witnessed statement head to be the Design's current one, each cited journal fact to precede the contribution, each cited contribution to be published, and each transcript range to be accounted, and admits the fact only beside its matching successful command receipt, whose one source witness per citation records what admission resolved; verification refuses a contribution without that receipt. `spice room history HANDLE` and `spice://task/HANDLE/room` keep every publication in one chronological page, render a contribution with its charge or question, the item it weighs with that item's text while its witnessed statement is still the Design's current head and otherwise only the item's handle marked as of an earlier statement, its text, and each source available or typed unavailable, never fabricated, and group the page's contributions by kind in journal order; `--contributions` (`?contributions`) pages only contributions. Untyped posts and packets stay conversation and are never reinterpreted. Writing or reading a contribution changes no task statement or workflow, claim, decision, or output authorization. |
| <a id="identity-design-maturity-is-bounded-advisory-evidence"></a>**Design maturity is bounded advisory evidence** | Every admitted profile-selected `room::noticed` request, every typed `room::contributed` record, and every `room::left` from a lane asked at a retained statement head incrementally update one Design's projection. Every contribution records the exact Design statement head its command witnessed. A leave declines at the newest retained head that asked its lane; a leave from an unasked lane is no decline, and a lane that contributes at that head counts as contributed instead. Each retained head reads as asked lanes that contributed, declined, and have yet to answer; the browser readout and `spice room awareness` show those counts, and room history shows each decline's clause. The projection keeps at most four exact recent statement heads, 64 sorted lane identities per set, and 32 question-item charge series, folds older heads into one fixed aggregate, and never scans room history while rendering. A charged contribution records its item's normalized text identity at admission, so a reorder keeps a series and a reword starts another; each series folds nonzero charges in journal order into fixed-size state. An item is quiet with no charge, unopposed while one sign has been seen, concurred when both signs have been seen and the current one-signed run holds two distinct lanes one of which earlier charged the opposite sign, or three distinct lanes, without burying the other side's last strength-2 charge unless the run holds one, and contested otherwise; a lane flipping its own sign sees both signs but cannot alone concur. Judged against the current statement's items, fresh means no contribution, steeped means at least `min(N, ceil(2 ln(1 + N)))` of the N current items have received a nonzero charge, some item concurs, and none is contested. Unopposed items count as heard; every question of one to four must be heard, then four of five or six and five of seven to eleven, so the heard share declines as a statement grows. Anything else is steeping and names the lowest contested item, else the lowest quiet one, else the lowest unopposed one, with the input it needs and how many items are still quiet. A removed item leaves the judgment. Zero charges, questions, requested reach, declines, and yield remain visible but never move an item. Crossing steeped readies a Design's first pass and narrows its invitation reach to the 0.16 floor; beyond that it supplies neutral operator attention only: it changes no standing, task, claim, decision, or authorization. |

## Steering

| Label | Invariant |
| --- | --- |
| <a id="steering-an-item-is-durable-before-delivery-is-attempted"></a>**An item is durable before delivery is attempted** | An item is accepted as one journal transaction before any delivery reader is notified. Ordinary submissions remain distinct: identical visible text sent twice persists as two items. The [outbox](#steering-an-outbox-submission-is-authored-tape-not-tool-metadata) deliberately reuses an identical complete body within one exact occupant. Submit cost does not grow with backlog depth. |
| <a id="steering-an-internal-directive-uses-its-journal-publication-instant"></a>**An internal directive uses its journal publication instant** | Resident-authored directives take their publication time and expiry base from the journal write that creates their fact and steering head. The head and fact share that exact instant; lifetime arithmetic never samples another clock. |
| <a id="steering-an-unaddressed-operator-message-selects-one-current-lane"></a>**An unaddressed operator message selects one current lane** | A message with no explicit recipient ranks every occupied or launchable vacant lane in cohorts before any score: occupied lanes holding no active claim, then vacant lanes holding none, and only then any lane holding an active claim.
