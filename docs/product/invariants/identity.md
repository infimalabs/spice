# Invariant register — Identity, steering, and work

## Identity and authority

| Label | Invariant |
| --- | --- |
| <a id="identity-a-task-s-inception-stamp-is-its-only-stored-identity"></a>**A task's inception stamp is its only stored identity** | A task's inception stamp is its only stored identity; the rendered handle derives a key from the project's rightmost segment and is never stored, so re-homing renames for free. |
| <a id="identity-the-stamp-is-a-fixed-width-order-preserving-base-encoding-of-inception-time"></a>**The stamp is a fixed-width, order-preserving base-52 encoding of inception time** | The stamp is a fixed-width, order-preserving base-52 encoding of inception time, so identity sorts as inception order without parsing. |
| <a id="identity-the-stamp-alphabet-omits-vowels-in-both-cases"></a>**The stamp alphabet omits vowels in both cases** | The stamp alphabet omits vowels in both cases, so a stamp cannot spell a word; collisions advance the instant rather than adding entropy. |
| <a id="identity-every-fact-has-exactly-one-authority"></a>**Every fact has exactly one authority** | Every fact has exactly one authority. Consumers ask the owner rather than re-deriving from a cheaper nearby source. |
| <a id="identity-each-authority-carries-its-own-freshness-counter"></a>**Each authority carries its own freshness counter** | Each authority carries its own freshness counter. There is no global revision. |
| <a id="identity-freshness-is-a-total-order-over-epoch-revision"></a>**Freshness is a total order over (epoch, revision)** | Freshness is a total order over (epoch, revision); epoch names the authority's counter generation and only rises, so an authority that restarted at a lower revision still supersedes. |
| <a id="identity-only-a-monotone-count-may-be-published-as-a-generation"></a>**Only a monotone count may be published as a generation** | Only a monotone count may be published as a generation; a hash identity is refused at the producer. |
| <a id="identity-a-chrome-payload-may-carry-any-subset-of-facets"></a>**A chrome payload may carry any subset of facets** | A chrome payload may carry any subset of facets, in any order, more than once; the reducer applies, ignores as stale, or refuses on authority mismatch. |
| <a id="identity-durable-authority-and-rebuildable-projection-never-share-a-file"></a>**Durable authority and rebuildable projection never share a file** | Durable authority and rebuildable projection never share a file, a connection, or a transaction. |
| <a id="identity-a-projection-family-must-declare-its-source"></a>**A projection family must declare its source** | A projection family must declare its source, its progress record, its replay horizon, its refill, and what it can still say when the source no longer reaches back. |
| <a id="identity-an-authority-migration-is-a-singular-forward-step"></a>**An authority migration is a singular forward step** | An authority migration is a singular forward step; refusing an unsupported shape without mutating it is a legitimate outcome that names the release owning the migration. |

## Steering

| Label | Invariant |
| --- | --- |
| <a id="steering-an-item-is-durable-before-delivery-is-attempted"></a>**An item is durable before delivery is attempted** | An item is durable before delivery is attempted: temp write, flush, link into place, flush the directory. |
| <a id="steering-reads-never-retire-an-item"></a>**Reads never retire an item** | Reads never retire an item. Only a semantic acknowledgement or refusal does. |
| <a id="steering-refusal-is-a-first-class-terminal-disposition"></a>**Refusal is a first-class terminal disposition** | Refusal is a first-class terminal disposition, recorded distinctly and surfaced everywhere acceptance is. |
| <a id="steering-escalation-is-driven-by-silence-measured-from-publication"></a>**Escalation is driven by silence measured from publication** | Escalation is driven by silence measured from publication, on a stable lineage key, in three named stages before expiry. |
| <a id="steering-an-item-that-cannot-be-delivered-is-dead-lettered"></a>**An item that cannot be delivered is dead-lettered** | An item that cannot be delivered is dead-lettered and its parked key reported with a requeue command. |
| <a id="steering-submit-cost-does-not-grow-with-backlog-depth"></a>**Submit cost does not grow with backlog depth** | Submit cost does not grow with backlog depth — identity is derived from names and stat metadata, never by reading queued bodies. |
| <a id="steering-pending-steering-reaches-the-agent-inside-non-shell-tool-spans"></a>**Pending steering reaches the agent inside non-shell tool spans** | Pending steering reaches the agent inside non-shell tool spans, not only at shell boundaries. |
| <a id="steering-the-steering-readout-is-suppressed-when-it-would-repeat-itself"></a>**The steering readout is suppressed when it would repeat itself** | The steering readout is suppressed when it would repeat itself. |
| <a id="steering-items-age-out-in-place-after-a-bounded-lifetime"></a>**Items age out in place after a bounded lifetime** | Items age out in place after a bounded lifetime rather than accumulating. |
| <a id="steering-the-filesystem-is-the-delivery-transport"></a>**The filesystem is the delivery transport** | The filesystem is the delivery transport; a separate durable store holds the lifecycle history that metrics, rehydration, and UI read. |
| <a id="steering-expiry-and-retirement-are-distinct-terminal-states"></a>**Expiry and retirement are distinct terminal states** | Expiry and retirement are distinct terminal states. An item nobody answered and an item that was refused are different facts, and collapsing them makes silence look like a decision. |
| <a id="steering-shell-instrumentation-is-one-shot-at-the-agent-s-own-command-boundary"></a>**Shell instrumentation is one-shot at the agent's own command boundary** | Shell instrumentation is one-shot at the agent's own command boundary: the wrapper runs exactly once per agent command and nothing beneath it is instrumented again. |
| <a id="steering-the-exactly-once-gate-is-structural"></a>**The exactly-once gate is structural** | The exactly-once gate is structural — distinct packaged environments rather than a counter — so there is no marker to read, forge, or lose. |
| <a id="steering-a-descendant-process-gets-the-user-s-shell-unmodified"></a>**A descendant process gets the user's shell unmodified** | A descendant process gets the user's shell unmodified, so a script that assumed a plain shell behaves identically inside and outside an agent. |
| <a id="steering-a-sourced-script-is-not-a-descendant-and-shares-the-immediate-shell-s-functions"></a>**A sourced script is not a descendant and shares the immediate shell's functions** | A sourced script is not a descendant and shares the immediate shell's functions: the boundary drawn is the process boundary, not a syntactic one. |
| <a id="steering-exactly-one-steering-connection-exists-per-agent-command"></a>**Exactly one steering connection exists per agent command** | Exactly one steering connection exists per agent command, bound to the immediate child's process identity; it survives that process forking and waiting and replacing itself, and closes when it exits even if a background descendant outlives it. |
| <a id="steering-steering-writes-to-the-wrapper-s-own-error-stream"></a>**Steering writes to the wrapper's own error stream** | Steering writes to the wrapper's own error stream, so a redirection inside a descendant cannot capture or silence it while redirecting the wrapper itself does. |
| <a id="steering-the-complete-top-level-command-string-reaches-the-wrapper-exactly-once"></a>**The complete top-level command string reaches the wrapper exactly once** | The complete top-level command string reaches the wrapper exactly once — the last point at which the command is still one string rather than a running process. |
| <a id="steering-steering-rides-the-output-of-the-commands-the-agent-runs"></a>**Steering rides the output of the commands the agent runs** | Steering rides the output of the commands the agent runs, so command cadence is message cadence: an agent that stops running commands stops being reachable. |

## Work, claims, and allocation

| Label | Invariant |
| --- | --- |
| <a id="work-at-most-one-active-claim-per-actor"></a>**At most one active claim per actor** | At most one active claim per actor. |
| <a id="work-claiming-is-atomic"></a>**Claiming is atomic** | Claiming is atomic: the activity marker and the claim metadata are set in one mutation, so a row is never active with no owner. |
| <a id="work-claims-carry-a-bounded-lease-and-a-context-window-around-them"></a>**Claims carry a bounded lease and a context window around them** | Claims carry a bounded lease and a context window around them, so a claim is reconstructible from the surrounding transcript. |
| <a id="work-a-stale-claim-may-be-taken-over"></a>**A stale claim may be taken over** | A stale claim may be taken over, and the takeover replaces exactly the stale claim the allocator observed. |
| <a id="work-a-displaced-claimant-is-notified-through-its-own-durable-steering-channel"></a>**A displaced claimant is notified through its own durable steering channel** | A displaced claimant is notified through its own durable steering channel. |
| <a id="work-renewal-carries-a-claim-to-the-successor-without-restarting-it"></a>**Renewal carries a claim to the successor without restarting it** | Renewal carries a claim to the successor without restarting it. |
| <a id="work-a-witness-record-distinguishes-an-intentional-end"></a>**A witness record distinguishes an intentional end** | A witness record distinguishes an intentional, announced end from no history at all. |
| <a id="work-queue-age-has-one-durable-origin"></a>**Queue age has one durable origin** | Queue age has one durable origin, and unrelated row modifications do not reset it. |
| <a id="work-allocation-ranks-in-a-fixed-ladder"></a>**Allocation ranks in a fixed ladder** | Allocation ranks in a fixed ladder: self-review class, then effective priority, then downstream weight, then a narrow urgency band, then peer spread, then locality. |
| <a id="work-a-prerequisite-inherits-the-highest-priority-it-transitively-unblocks"></a>**A prerequisite inherits the highest priority it transitively unblocks** | A prerequisite inherits the highest priority it transitively unblocks. |
| <a id="work-self-authored-review-is-ranked-last-never-excluded"></a>**Self-authored review is ranked last, never excluded** | Self-authored review is ranked last, never excluded; a quiet board hands an actor its own review rather than stalling. |
| <a id="work-locality-is-the-final-tie-break-and-never-overrides-the-graph"></a>**Locality is the final tie-break and never overrides the graph** | Locality is the final tie-break and never overrides the graph. |
| <a id="work-every-assignable-task-names-an-origin-realm"></a>**Every assignable task names an origin realm** | Every assignable task names an origin realm — the steering or the parent task that caused it. |
| <a id="work-a-phase-advance-is-a-publication"></a>**A phase advance is a publication** | A phase advance is a publication, recoverable from the authority's own history without a parallel event log. |
| <a id="work-a-review-that-changes-nothing-still-advances-the-phase"></a>**A review that changes nothing still advances the phase** | A review that changes nothing still advances the phase, so absence of a commit is not absence of review. |
| <a id="work-implementation-work-is-refused"></a>**Implementation work is refused** | Implementation work is refused while the actor holds a plan-phase claim. |
| <a id="work-hidden-channels-keep-admissions-private"></a>**Hidden channels keep admissions private** | Hidden channels exist so that admitting a mistake is cheap and private. |
| <a id="work-a-lapsed-claim-counts-as-stale"></a>**A lapsed claim counts as stale** | A lapsed claim counts as *stale*, not as held by a peer. The allocator takes stale claims over when it can, so one still on the board lost a race or is hidden — a different reason to be parked than an owner actively working it. |
| <a id="work-a-dry-allocator-reports-the-board"></a>**A dry allocator reports the board** | A dry allocator reports the board rather than pointing at it: each parked category is named with the reason it is parked, and a populated board is stated to be the expected answer rather than an error or missed work. |
| <a id="work-permission-to-stop-is-bound-to-the-one-condition-that-grants-it"></a>**Permission to stop is bound to the one condition that grants it** | Permission to stop is bound to the one condition that grants it — a dry allocator immediately after asking for work. Lookalikes are called out by name so neither a quiet-looking board nor a low pending count reads as a licence to spin down. |
| <a id="work-affinity-and-anti-affinity-address-one-coordinate"></a>**Affinity and anti-affinity address one coordinate** | Affinity and anti-affinity address one coordinate — the (project, phase) cell — read in two directions, so neither can be tuned into overwhelming the other. |
| <a id="work-anti-affinity-reads-peers-across-the-whole-board"></a>**Anti-affinity reads peers across the whole board** | Anti-affinity reads peers across the whole board, not only through the actor's own route: spreading is about where the agents are, not where this actor's candidates are. |
| <a id="work-anti-affinity-is-a-preference-never-an-exclusion"></a>**Anti-affinity is a preference, never an exclusion** | Anti-affinity is a preference, never an exclusion; when every ready row sits in a crowded cell the actor is still handed one. |
| <a id="work-affinity-is-measured-from-the-actor-s-most-recently-claimed-cell-alone"></a>**Affinity is measured from the actor's most recently claimed cell alone** | Affinity is measured from the actor's most recently claimed cell alone, with no accumulated history, so moving to a new area is paid for exactly once. |
| <a id="work-movement-counts-project-and-phase-separately-and-sums-the-two"></a>**Movement counts project and phase separately and sums the two** | Movement counts project and phase separately and sums the two, so changing both costs strictly more than changing either alone. Leaving a project for the same phase and changing phase inside a project cost the same; only compounding the two is penalised, and that gradient is what makes an agent finish an area. |
| <a id="work-locality-applies-only-inside-a-narrow-urgency-band"></a>**Locality applies only inside a narrow urgency band** | Both locality terms are gated by a narrow urgency band beneath the top of the row's own group and neutralized outside it, because a merely lower rank still decides every comparison the levels above it tie on. |
| <a id="work-tasks-without-acceptance-enter-a-plan-phase"></a>**Tasks without acceptance enter a plan phase** | A task captured with neither acceptance nor a named flow has a plan phase prepended to its flow rather than being refused or filed vague: absent acceptance is unfinished thinking, not an error. |
| <a id="work-a-plan-phase-closes-only-when-acceptance-exists"></a>**A plan phase closes only when acceptance exists** | A plan phase closes only when acceptance exists — on the task itself or on at least one connected pending child. |
| <a id="work-a-plan-only-flow-must-leave-a-connected-child-carrying-acceptance"></a>**A plan-only flow must leave a connected child carrying acceptance** | A plan-only flow must leave a connected child carrying acceptance, because the board it produces is its entire product. |
| <a id="work-the-prepended-phase-is-visible-as-a-phase"></a>**The prepended phase is visible as a phase** | The prepended phase is visible as a phase, not as a flag, so the board explains the task's behaviour in a vocabulary the operator already reads. |
