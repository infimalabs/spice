# Invariant register — Checks

[Invariant register](../invariants.md) · [Spice product model](../README.md)
## Checks

| Label | Invariant |
| --- | --- |
| <a id="checks-check-settings-have-one-source"></a>**Check settings have one source** | Check settings live in one place that hooks, studies, docs, and tests all read. |
| <a id="checks-direct-study-commands-may-take-flags"></a>**Direct study commands may take flags** | Direct study commands may take flags; the commit gates run the defaults. |
| <a id="checks-flex-is-headroom-not-a-new-limit"></a>**Flex is headroom, not a new limit** | Flex is headroom, not a new limit: the first breach latches a file to its base limit until it shrinks back under. |
| <a id="checks-a-passing-gate-prunes-sticky-state-that-no-longer-measures-over-base"></a>**A passing gate prunes sticky state that no longer measures over base** | A passing gate prunes sticky state that no longer measures over base. |
| <a id="checks-sticky-latches-are-lane-local"></a>**Sticky latches are lane-local** | Sticky latches are lane-local; live flex claims are shared, so peers coordinate ownership of the same slice. |
| <a id="checks-ceilings-are-jittered-per-actor-and-path"></a>**Ceilings are jittered per actor and path** | Ceilings are jittered per actor and path so two agents do not independently refactor the same file. |
| <a id="checks-wide-measures-diff-against-a-baseline"></a>**Wide measures diff against a baseline** | Wide measures diff against a baseline so only regressions fail. |
| <a id="checks-some-ceilings-are-absolute-zero"></a>**Some ceilings are absolute zero** | Some ceilings are absolute zero — test-only public symbols, assertion-free tests. |
| <a id="checks-a-study-that-finds-something-files-a-deferred"></a>**A study that finds something files a deferred** | A study that finds something files a deferred, traceable task rather than only printing. |
| <a id="checks-dirty-work-renders-the-same-pressure-as-steering"></a>**Dirty work renders the same pressure as steering** | Dirty work renders the same pressure as steering, not as a block. |
| <a id="checks-a-gate-is-never-closed-by-weakening-it"></a>**A gate is never closed by weakening it** | A gate is never closed by weakening it. |
| <a id="checks-tests-assert-present-observable-properties-in-preference-to-absence"></a>**Tests assert present, observable properties in preference to absence** | Tests assert present, observable properties in preference to absence. |
| <a id="checks-the-gate-roster-is-ordered-and-the-order-is-part-of-the-contract"></a>**The gate roster is ordered and the order is part of the contract** | The gate roster is ordered and the order is part of the contract: integrity before shape, shape before staging, staging before anything that reads staged content. |
| <a id="checks-each-step-s-failure-is-collected-and-the-run-continues"></a>**Each step's failure is collected and the run continues** | Each step's failure is collected and the run continues, so one commit attempt reports the whole picture rather than the first thing that went wrong. |
| <a id="checks-a-clean-run-prints-nothing"></a>**A clean run prints nothing** | A clean run prints nothing. Silence is the success signal. |
| <a id="checks-a-study-that-cannot-execute-raises"></a>**A study that cannot execute raises** | A study that cannot execute raises, naming the capability it needs; it never returns zero findings. |
| <a id="checks-a-clean-result-echoes-the-limits-it-actually-applied"></a>**A clean result echoes the limits it actually applied** | A clean result echoes the limits it actually applied, so a pass is evidence about which thresholds were in force. |
| <a id="checks-a-study-with-no-applicable-input-passes-silently"></a>**A study with no applicable input passes silently** | A study with no applicable input passes silently; empty scope and empty findings are the same verdict, and both differ from cannot-run. |
| <a id="checks-direct-runs-are-tri-state"></a>**Direct runs are tri-state** | Direct runs are tri-state — clean, findings, cannot-run. The commit gate collapses the last two, because to the committer they mean the same thing. |
| <a id="checks-latch-writes-are-held-until-the-whole-run-is-accepted"></a>**Latch writes are held until the whole run is accepted** | Latch writes are held until the whole run is accepted, so a refused commit leaves the pressure ledgers as it found them and the next attempt meets the limits this one reported. |
| <a id="checks-steps-contributed-by-configuration-are-skipped-unless-the-staging-step-passed"></a>**Steps contributed by configuration are skipped unless the staging step passed** | Steps contributed by configuration are skipped unless the staging step passed, so an extension never runs against a half-staged tree. |
| <a id="checks-the-flex-ceiling-is-an-exact-integer-ratio-over-the-base"></a>**The flex ceiling is an exact integer ratio over the base** | The flex ceiling is an exact integer ratio over the base, computed with integer arithmetic, so it is the same number on every machine. |
| <a id="checks-a-refusal-caused-by-a-latch"></a>**A refusal caused by a latch** | A refusal caused by a latch rather than by the value says so and names the ledger holding it. Over-the-limit and held-at-base are different diagnoses. |
| <a id="checks-a-latch-is-retired-the-moment-any-scan-measures-its-subject-at-or-under-base"></a>**A latch is retired the moment any scan measures its subject at or under base** | A latch is retired the moment any scan measures its subject at or under base — including during a run that fails for other reasons. |
| <a id="checks-an-emptied-ledger-is-deleted"></a>**An emptied ledger is deleted** | An emptied ledger is deleted rather than left as an empty file, so a healed subject leaves no trace. |
| <a id="checks-latches-follow-renames-additively"></a>**Latches follow renames additively** | Latches follow renames additively: a renamed subject carries its latch forward without the old name being silently dropped. |
| <a id="checks-jitter-is-applied-over-the-headroom"></a>**Jitter is applied over the headroom** | Jitter is applied over the headroom rather than over the limit, so a jittered ceiling can never fall below base. |
| <a id="checks-the-jitter-seed-is-who-authored-the-content"></a>**The jitter seed is who authored the content** | The jitter seed is who authored the content, resolved from published history — not who is running the scan. Two agents reading one file see one ceiling. |
| <a id="checks-jitter-is-deterministic"></a>**Jitter is deterministic** | Jitter is deterministic: the same subject and actor always resolve to the same ceiling, so a limit never appears to move under unchanged content. |
| <a id="checks-live-breaches-on-shared-subjects-are-claimed"></a>**Live breaches on shared subjects are claimed** | Live breaches on shared subjects are claimed, and claims are time-boxed and self-pruning; an abandoned claim expires without anyone collecting it. |
| <a id="checks-the-earliest-claimant-owns-a-contested-subject"></a>**The earliest claimant owns a contested subject** | The earliest claimant owns a contested subject, with a deterministic tie-break, so ownership never depends on scan order. |
| <a id="checks-a-finding-whose-subject-is-held-by-a-peer-informs-and-passes"></a>**A finding whose subject is held by a peer informs and passes** | A finding whose subject is held by a peer informs and passes; only unclaimed findings block. The redirect names the holder and the expiry. |
| <a id="checks-claims-require-a-named-actor"></a>**Claims require a named actor** | Claiming requires a named actor, so a read-only scan neither records claims nor observes them and investigation never perturbs shared state. |
| <a id="checks-a-limit-has-one-declared-kind"></a>**A limit has one declared kind** | A limit is a threshold, a set equality, a differential, or binary — and a measure declares which kind it is. |
| <a id="checks-a-measure-whose-baseline-cannot-be-read-must-not-report-clean"></a>**A measure whose baseline cannot be read must not report clean** | A measure whose baseline cannot be read must not report clean; a missing baseline and an empty baseline produce the same set and must not produce the same verdict. |
| <a id="checks-selectors-name-files"></a>**Selectors name files** | Selectors name files; content is read from the working tree, so a study reports on the tree the author is looking at. |
| <a id="checks-selectors-are-mutually-exclusive"></a>**Selectors are mutually exclusive** | Selectors are mutually exclusive; ambiguous selection is refused rather than resolved by precedence. |
| <a id="checks-the-appliance-s-own-runtime-state-is-excluded-from-every-selector"></a>**The appliance's own runtime state is excluded from every selector** | The appliance's own runtime state is excluded from every selector, so a study can never take its bookkeeping as evidence about the repository. |
| <a id="checks-the-fully-staged-rule-is-the-intersection-of-staged-and-unstaged-names"></a>**The fully-staged rule is the intersection of staged and unstaged names** | The fully-staged rule is the intersection of staged and unstaged names: a partly staged file is refused, because every other measure would judge a tree that is not the one being committed. |
| <a id="checks-every-waiver-is-declared-and-enumerable"></a>**Every waiver is declared and enumerable** | Every waiver is declared and enumerable. There is no silent suppression. |
| <a id="checks-an-allowlist-names-the-specific-thing-it-permits"></a>**An allowlist names the specific thing it permits** | An allowlist names the specific thing it permits; a count is never a waiver, because permitting three of these permits the wrong three. |
| <a id="checks-a-scoped-rule-retunes-a-bound-over-a-declared-path-set"></a>**A scoped rule retunes a bound over a declared path set** | A scoped rule retunes a bound over a declared path set. It changes the limit and cannot disable the measure. |
| <a id="checks-a-step-may-be-disabled-by-configuration"></a>**A step may be disabled by configuration** | A step may be disabled by configuration, and the check system audits its own disablements, so turning a gate off is a visible act rather than an absence. |
| <a id="checks-waivers-are-tracked"></a>**Waivers are tracked** | Waivers are tracked, so every clone sees the same exceptions; an exception that lives on one machine is a local divergence, not an exception. |
| <a id="checks-only-registered-instruments-may-file-work"></a>**Only registered instruments may file work** | Only registered instruments may file work, and only when asked. A study does not decide on its own to put something on the board. |
| <a id="checks-filing-is-idempotent-against-a-finding-s-identity-within-its-project"></a>**Filing is idempotent against a finding's identity within its project** | Filing is idempotent against a finding's identity within its project: re-running an instrument reuses the open task rather than filing a second. |
| <a id="checks-a-finding-s-identity-survives-the-board-s-own-normalization"></a>**A finding's identity survives the board's own normalization** | A finding's identity survives the board's own normalization, which is what makes it a key rather than a label. |
| <a id="checks-a-completed-predecessor-never-blocks-re-filing"></a>**A completed predecessor never blocks re-filing** | A completed predecessor never blocks re-filing; recurrence files afresh with an annotation naming the resolved task, so the link is recorded rather than inferred. |
| <a id="checks-study-work-is-filed-deferred-and-carries-no-due-date"></a>**Study work is filed deferred and carries no due date** | Study work is filed deferred and carries no due date, so time spent parked does not consume the priority clock. |
| <a id="checks-a-study-task-carries-the-same-required-origin-as-any-other-task"></a>**A study task carries the same required origin as any other task** | A study task carries the same required origin as any other task, inheriting the acting claim when none is given. |
| <a id="checks-findings-and-filed-work-are-coextensive"></a>**Findings and filed work are coextensive** | Findings and filed work are coextensive; an instrument reports what it found and dispatch decides what becomes a task, so an instrument cannot pre-seed or suppress its own filing. |
| <a id="checks-a-measure-that-must-run-the-code-runs-it-on-a-disposable-copy-of-the-caller-s"></a>**A measure that must run the code runs it on a disposable copy of the caller's** | A measure that must run the code runs it on a disposable copy of the caller's effective tested content, which is broader than any commit-time selector. |
| <a id="checks-the-caller-s-checkout-stays-read-only-for-the-whole-measurement"></a>**The caller's checkout stays read-only for the whole measurement** | The caller's checkout stays read-only for the whole measurement, so concurrent control-plane commands keep observing reality. |
| <a id="checks-retirement-of-a-disposable-copy-is-atomic-by-rename"></a>**Retirement of a disposable copy is atomic by rename** | Retirement of a disposable copy is atomic by rename, so a crash mid-delete leaves debris that is unambiguously dead rather than half-live. |
| <a id="checks-each-disposable-copy-records-its-owning-process-and-the-next-run-scavenges-abandoned-ones"></a>**Each disposable copy records its owning process and the next run scavenges abandoned ones** | Each disposable copy records its owning process and the next run scavenges abandoned ones, so cleanup is a property of the next run rather than of the crashed one. |
| <a id="checks-configuration-fails-loudly"></a>**Configuration fails loudly** | Configuration fails loudly: unknown keys are rejected at load in every layer, and an invalid bound is an error rather than a silent fall back to the default. |
